# Campus Emergency Control System

A Java 17 + Spring Boot + MySQL web application based on the supplied PBL synopsis.

## Included modules
- User registration/login (passwords are BCrypt-hashed)
- User emergency reporting and personal incident history
- Admin overview, priority queue, team assignment and analytics
- Team portal status updates
- Safety advice by emergency type
- MySQL persistence through Spring Data JPA / Hibernate
- Black and red responsive web UI

## Requirements
1. Java JDK 17 or later
2. Maven (or use the Maven wrapper generated by VS Code / installed Maven)
3. MySQL Server 8.x
4. Visual Studio Code with the Extension Pack for Java and Spring Boot Extension Pack

**MySQL Workbench is optional.** It is only a graphical database client. MySQL Server is the actual database engine and must be installed and running.

## Database setup (macOS)
1. Install MySQL Community Server from https://dev.mysql.com/downloads/mysql/
2. During installation, set and remember the root password.
3. Start the MySQL server from System Settings or the MySQL preference pane.
4. Open Terminal and run:
   ```bash
   mysql -u root -p
   ```
5. Enter your password, then run:
   ```sql
   CREATE DATABASE campus_emergency_db;
   EXIT;
   ```
6. Open `src/main/resources/application.properties` and replace `CHANGE_THIS_PASSWORD` with your MySQL root password.

You do not need MySQL Workbench. You can use the MySQL command line. For a graphical alternative, install MySQL Workbench separately later.

## Run in VS Code
1. Extract the ZIP file.
2. VS Code → File → Open Folder → select `CampusEmergencyControlSystem`.
3. Install the recommended Java and Spring extensions if prompted.
4. Ensure JDK 17 is selected.
5. In the VS Code terminal, run:
   ```bash
   mvn spring-boot:run
   ```
6. Open http://localhost:8080

If Maven is not installed, install it with Homebrew (`brew install maven`) or use the Maven project import/build controls in VS Code.

## Java concepts demonstrated
- Classes and objects: entities and service classes
- Encapsulation: private entity fields with accessors
- Inheritance: `AbstractEmergencyHandler` extended by specialized handlers
- Polymorphism: `EmergencyResponse` implementations selected by emergency type
- Abstraction and interfaces: `EmergencyResponse`
- Constructors: model and handler initialization
- Exception handling: service exceptions and REST error handling
- Collections: `ArrayList`, `HashMap`
- `PriorityQueue`: orders active incidents by P1–P4 and report time
- JPA/Hibernate: entity persistence and repositories
- REST APIs: `ApiController`
- Authentication: session login and BCrypt password hashing

## Important prototype limitations
This is an educational prototype, not a certified emergency dispatch system. It does not send SMS/push notifications, use GPS, calculate map-based ETA, or guarantee real-time dispatch. ETA is a simple team estimate. The UI's SOS flow creates a report; it does not contact emergency services. Always call 112 in India for immediate life-threatening emergencies.
Before real-world use, add Spring Security authorization, CSRF protection, audit controls, team-member mapping, rate limiting, privacy safeguards, tested escalation workflows, and professional emergency-response review.
